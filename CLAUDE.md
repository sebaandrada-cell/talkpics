# TalkPics

Free communication app (AAC) for non-speaking autistic people and their families. Built by Sebastián for his daughter Amelia. Single-file PWA, no build step, no backend.

## Files
- `TalkPics.html`: the whole app (HTML, CSS, JS in one file). Data lives in IndexedDB on the device.
- `index.html`: landing page in the same 17 languages as the app (each text is a group of `<span data-xx>`; English is the default shown before JS runs). A dropdown (`#langSel`) switches language; every link to the app gets `?lang=` with the language on screen. The tab title and the QR image alt text follow the language (`TITLES`, `QR_ALT` in `setLang`); the share preview (`og:*`) and meta description are static, in Spanish + English, because link previews cannot change language. The printable sheet `TalkPics-QR-hoja.pdf` is Spanish only (other languages pending native review).
- `sw.js`: service worker. Change `VERSION` on every release so installed copies update.
- `manifest.webmanifest`, icons, QR codes, `TalkPics-QR-hoja.pdf`: PWA and print material.

## Publishing
GitHub Pages serves the `TalkPics` branch (root) at https://sebaandrada-cell.github.io/talkpics/ . Pushing to `TalkPics` publishes immediately to real families. `main` is only an empty root (the account default for new projects) and holds no app files: do all work on `TalkPics` or on a short branch from it, and open pull requests against `TalkPics`, never `main`. Short links: https://tinyurl.com/talkpics-caa (landing), https://tinyurl.com/talkpics-app (app). Never change file names or paths: the printed QR sheets and shared links point to them.

## Languages
App: Spanish (`es`), Catalan (`ca`), English (`en`, the fallback when nothing else matches), French (`fr`), Italian (`it`), Portuguese (`pt`, Brazilian wording, prefers a pt-BR voice), German (`de`), Latvian (`lv`), Ukrainian (`uk`), Russian (`ru`), Nepali (`ne`, Devanagari script, nepali label `नेपाली`), Hebrew (`he`, label `עברית`), Arabic (`ar`, Modern Standard Arabic, label `العربية`), Simplified Chinese (`zh-hans`, label `简体中文`), Traditional Chinese (`zh-hant`, label `繁體中文`), Japanese (`ja`, label `日本語`) and Korean (`ko`, label `한국어`). Language pickers (app Settings and landing dropdown) show only the language name in its own language, never flags (decided 2026-11-06: a language is not a country, and a flag would exclude part of its speakers, e.g. Russian speakers in Latvia or Ukraine, Portuguese in Portugal vs Brazil). The list lives in `LANGS` (label, voice preference, BCP-47 code, `rtl:true` for he/ar); the settings sheet builds its language buttons from it.
- Right-to-left (added 2026-11-08 with Hebrew and Arabic): the app (`applyLang`) and the landing (`setLang`) set `dir="rtl"` on `<html>` for he/ar and `ltr` otherwise. Everything that was placed with left/right (header title, star and pencil on cards, zoom close button, switch knobs, strip chip remove button; landing brand, mock gear, text-align of lists and forms, list padding, the hidden honeypot field) has a `[dir=rtl]` override at the end of each `<style>`. A new rule with `left`/`right`, `margin-left`/`-right`, `padding-left`/`-right` or `text-align:left` needs its RTL mirror there too. Never put something at a big negative `left` in RTL (it opens horizontal scroll): the honeypot uses `right:-9999px` in RTL. In RTL texts use `←` where English uses `→` (sort A→Z, ✏️ → 🎙️), because arrows are not mirrored by the browser.
- UI strings: `I18N` holds es/ca/en; `I18N_EXTRA` adds the newer languages and the Catalan keys that used to be missing. `{N}` inside a string is replaced by `STRIP_MAX`; `hManyAdded` may contain `{n}` (number of pictures). Missing keys fall back to English for the newer languages and to Spanish for es/ca.
- Card and category names: es/ca/en keep their historic storage (`name` = Spanish, `nameCa`, `nameEn`). The newer languages are NOT stored on the cards: `BASE_NAMES[lang][spanishName]` and `BASE_CATS[lang][catId]` translate the base set at display time, and a family's own translation goes in `p.names[lang]` (edit sheet field "name in <language>", only shown in the newer languages). No migration was needed; never rename the Spanish base names, they are the lookup key.
- Voice: each language only uses voices of its own language (Catalan may fall back to a Spanish voice). If the device has no voice for the chosen language, Settings shows a notice suggesting installing one or recording a family member. Do not fall back to another language's voice: it would mispronounce the words.
- ARASAAC search has no Latvian and no Nepali. Hebrew and Arabic ARE in `ARA_LANGS`, but their support in the ARASAAC API was not verified (the sandbox could not reach it): the search tries he/ar first and, if that request fails or finds nothing, English then Spanish; the connection error is only shown when every attempt failed. If ARASAAC confirms it has no he/ar, remove them from `ARA_LANGS`. Also: `ARA_LANGS` lists the supported ones (`ne` and `lv` are deliberately NOT in it); Latvian and Nepali searches go to English, then Spanish. A query typed in Devanagari finds nothing there, so the Nepali hint tells people to search in English (e.g. `eat`). ARASAAC answers 404 when it finds nothing, which the app treats as "no results", not as a connection error.
- First visit, same rule in the app and the landing: a valid `?lang=` wins; otherwise the first entry of `navigator.languages` (whole list, by base code: `pt-BR` -> `pt`; the old Hebrew code `iw` counts as `he`; `zh-TW`, `zh-HK`, `zh-MO` and anything with `Hant` count as `zh-hant`, any other `zh` (also `?lang=zh`) as `zh-hans`; the function is `normLang` in both files) that TalkPics supports; otherwise English. There is no Spanish default anymore. After the first visit the app keeps the language saved in Settings: a plain `?lang=` (shared links, QR) does not change it. Exception (decided 2026-11-06 after Sebastián tested it): the landing's "Open the app" buttons add `&from=web`, and then the language chosen on the landing replaces the saved one; the app removes `from` from the URL afterwards. A stored voice is only used if it belongs to the current language, and changing language refreshes the voice list. Incognito windows in Chrome share storage while any of them is open, so a language chosen in one incognito tab sticks in the others.
- Translations of the newer languages were written without native review. Latvian was promised to the Latvian Autism Association; ask a native speaker to review before relying on it.
- Nepali (added 2026-11-07 on request of AutismCare Nepal Society, ACNS, who asked for it and were asked to review it): translation NOT reviewed by a native speaker. Do not present it as verified. When a reviewed list comes back from ACNS, apply it to `BASE_NAMES.ne`, `BASE_CATS.ne`, `V17_NAMES.ne`, `I18N_EXTRA.ne`, `A11Y_STR.ne`, `MODEL_LINE.ne` in `TalkPics.html` and to the `data-ne` spans and the `ne` entries of `TP_MSG`, `CF_*`, `QR_ALT`, `TITLES` in `index.html`. Nepali needs a Devanagari font on the device (all current Android and iOS have one). `LANG_LINE` only holds es/ca/en (it replaces the old flags line); the newer languages carry their own language line inside `welcomeBody`, so `ne` is not added there. The landing says "17 languages" in the advantages text (#81, and the list in #82) and in the static `meta description` / `og:description`; update those when adding another language.
- Hebrew and Arabic (added 2026-11-08 at the request of Beit Issie Shapiro, Israel, who needs both): translations NOT reviewed by native speakers; ask Beit Issie Shapiro to review before presenting them as verified. Arabic is Modern Standard Arabic only (no dialect entry; Palestinian and other dialects would be a family's own names via `p.names.ar`). Both languages mark gender: card names (Feliz, Cansado, Tengo hambre, No sé…) use the masculine singular like the Spanish source, so a family with a girl may want to rename them (edit sheet). The Hebrew interface avoids gender with infinitives and "אפשר ל…"; the Arabic interface uses the usual masculine imperative. Arabic action cards are first person ("ألعب" = I play), Hebrew ones infinitive ("לשחק"). When reviewed lists come back, apply them to `BASE_NAMES`, `BASE_CATS`, `V17_NAMES`, `I18N_EXTRA`, `A11Y_STR`, `MODEL_LINE` (keys `he`/`ar`) in `TalkPics.html` and to the `data-he`/`data-ar` spans and the `he`/`ar` entries of `TP_MSG`, `CF_*`, `QR_ALT`, `TITLES` in `index.html`.
- Chinese, Japanese and Korean (added 2026-11-08, nobody requested them yet; translations NOT reviewed by native speakers). Codes are lowercase with a hyphen: `zh-hans` and `zh-hant` (the `?lang=` value is lowercased, so never use `zh-Hans`). `<html lang>` takes the code, which also makes the browser pick Chinese glyphs. On the landing they are `data-zh-hans`/`data-zh-hant` spans and `body.zh-hans` classes. Simplified = mainland vocabulary, Mandarin voice (`zh-CN`, then `zh-TW`; never a Cantonese `zh-HK`/`yue` voice). Traditional = Taiwan vocabulary, voice `zh-TW`, then Cantonese `zh-HK`/`yue` (for Hong Kong), then `zh-CN`. ARASAAC is asked with `zh` for both Chinese (`ARA_CODE`), and with `ja`/`ko`, unverified, with the usual English/Spanish fallback. Japanese: interface in polite です/ます with kanji; cards and categories in hiragana/katakana only, casual child speech, because young children do not read kanji. Korean: interface and cards in 해요체 (polite-informal, works at home and at school; chosen by Sebastián); nouns stay plain. No gender in these four languages. CSS: CJK header labels get `white-space:nowrap` (otherwise they break one character per line) and Korean uses `word-break:keep-all` (breaks by word, as Koreans write).
- Editor header on phones (≤440 px, `body.care`): the mode label goes under "TalkPics", the 🗣️ is hidden and the buttons are a bit tighter (touch targets stay ≥64 px), so the header fits 390 px in all 17 languages (it used to overflow in every language). At 375 px German and Russian still overflow by a few px.
