# TalkPics

Free communication app (AAC) for non-speaking autistic people and their families. Built by Sebastián for his daughter Amelia. Single-file PWA, no build step, no backend.

## Files
- `TalkPics.html`: the whole app (HTML, CSS, JS in one file). Data lives in IndexedDB on the device. The tab title follows the language: `applyLang` sets `document.title` from `APP_TITLES`, which holds the same 17 texts as `TITLES` in `index.html` (keep both in step); the static `<title>` is the English one, shown before JS runs.
- `index.html`: landing page in the same 17 languages as the app (each text is a group of `<span data-xx>`; English is the default shown before JS runs). A dropdown (`#langSel`) switches language; every link to the app gets `?lang=` with the language on screen. The tab title and the QR image alt text follow the language (`TITLES`, `QR_ALT` in `setLang`); the share preview (`og:*`) and meta description are static, in Spanish + English, because link previews cannot change language. The printable sheet `TalkPics-QR-hoja.pdf` is Spanish only (other languages pending native review).
- `sw.js`: service worker. Change `VERSION` on every release so installed copies update.
- `manifest.webmanifest`, icons, QR codes, `TalkPics-QR-hoja.pdf`: PWA and print material.
- `video/add-photo-<lang>.mp4` and `.jpg` (added 2026-11-16): an 18-second silent screen recording of the app, one per language, shown on the landing under "How it works" (`#demoVid`; `setLang` swaps `src` and `poster`). It shows: hold the lock, ＋ Photo, pick a photo from the gallery, remove the background, type the name, Save, Done, then tap the new card. Recorded with Playwright in headless Chrome at 390×844 with a drawn touch marker; the photo is the scikit-image "coffee" sample (CC0, Rachel Michetti), never a family photo. H.264, CRF 30, about 160 KB each. The caption under the video describes every step in text (alternative for a silent video, WCAG 1.2.1). Re-record them when the add-photo flow or its texts change. `sw.js` never caches `/video/` or Range requests (a 206 cannot be cached and would break playback).

## Publishing
GitHub Pages serves the `TalkPics` branch (root) at https://sebaandrada-cell.github.io/talkpics/ . Pushing to `TalkPics` publishes immediately to real families. `main` is only an empty root (the account default for new projects) and holds no app files: do all work on `TalkPics` or on a short branch from it, and open pull requests against `TalkPics`, never `main`. Short links: https://tinyurl.com/talkpics-caa (landing), https://tinyurl.com/talkpics-app (app). Never change file names or paths: the printed QR sheets and shared links point to them.

## Languages
App: Spanish (`es`), Catalan (`ca`), English (`en`, the fallback when nothing else matches), French (`fr`), Italian (`it`), Portuguese (`pt`, Brazilian wording, prefers a pt-BR voice), German (`de`), Latvian (`lv`), Ukrainian (`uk`), Russian (`ru`), Nepali (`ne`, Devanagari script, nepali label `नेपाली`), Hebrew (`he`, label `עברית`), Arabic (`ar`, Modern Standard Arabic, label `العربية`), Simplified Chinese (`zh-hans`, label `简体中文`), Traditional Chinese (`zh-hant`, label `繁體中文`), Japanese (`ja`, label `日本語`) and Korean (`ko`, label `한국어`). Language pickers (app Settings and landing dropdown) show only the language name in its own language, never flags (decided 2026-11-06: a language is not a country, and a flag would exclude part of its speakers, e.g. Russian speakers in Latvia or Ukraine, Portuguese in Portugal vs Brazil). The list lives in `LANGS` (label, voice preference, BCP-47 code, `rtl:true` for he/ar); the settings sheet builds its language buttons from it.
- Right-to-left (added 2026-11-08 with Hebrew and Arabic): the app (`applyLang`) and the landing (`setLang`) set `dir="rtl"` on `<html>` for he/ar and `ltr` otherwise. Everything that was placed with left/right (header title, star and pencil on cards, zoom close button, switch knobs, strip chip remove button; landing brand, mock gear, text-align of lists and forms, list padding, the hidden honeypot field) has a `[dir=rtl]` override at the end of each `<style>`. A new rule with `left`/`right`, `margin-left`/`-right`, `padding-left`/`-right` or `text-align:left` needs its RTL mirror there too. Never put something at a big negative `left` in RTL (it opens horizontal scroll): the honeypot uses `right:-9999px` in RTL. In RTL texts use `←` where English uses `→` (sort A→Z, ✏️ → 🎙️), because arrows are not mirrored by the browser.
- UI strings: `I18N` holds es/ca/en; `I18N_EXTRA` adds the newer languages and the Catalan keys that used to be missing. `{N}` inside a string is replaced by `STRIP_MAX`; `hManyAdded` may contain `{n}` (number of pictures). Missing keys fall back to English for the newer languages and to Spanish for es/ca.
- Card and category names: es/ca/en keep their historic storage (`name` = Spanish, `nameCa`, `nameEn`). The newer languages are NOT stored on the cards: `BASE_NAMES[lang][spanishName]` and `BASE_CATS[lang][catId]` translate the base set at display time, and a family's own translation goes in `p.names[lang]` (edit sheet field "name in <language>", only shown in the newer languages). No migration was needed; never rename the Spanish base names, they are the lookup key.
- Voice: each language only uses voices of its own language (Catalan may fall back to a Spanish voice). If the device has no voice for the chosen language, Settings shows a notice suggesting installing one or recording a family member. Do not fall back to another language's voice: it would mispronounce the words. Since 2026-11-17 the same notice (`voiceNone`) also shows above the board (`#voiceWarn`, `updateVoiceWarn`), in child and editor mode, because almost nobody saw it inside Settings: Autism Canada reported that French was "spoken in English", which is what a browser does when the device has voices but none in French (the app sends the French word tagged `fr-FR` with no voice and the browser reads it with its default one). It shows only when "Speak aloud" is on and the device has at least one voice but none for the language (an empty voice list may still be loading, so it stays hidden). The ✕ closes it for that language for good (`settings.voiceWarnOff`, a list of language codes; a missing key means never closed). Which device Autism Canada used was not confirmed.
- ARASAAC languages, verified against the live API on 2026-11-16 (its own list: an, ar, bg, br, ca, cs, da, de, el, en, es, et, eu, fa, fr, gl, he, hi, hr, hu, it, is, ko, lt, lv, mk, nb, nl, pl, pt, ro, ru, sk, sl, sq, sv, sr, tr, val, uk, zh): he, ar, zh and ko work; ja and ne are rejected (HTTP 400), so `ja` was removed from `ARA_LANGS`; lv is accepted but returned nothing for the four words tried. The search tries the app language first and, if that request fails or finds nothing, English then Spanish; the connection error is only shown when every attempt failed. Also: `ARA_LANGS` lists the supported ones (`ne` and `lv` are deliberately NOT in it); Latvian and Nepali searches go to English, then Spanish. A query typed in Devanagari finds nothing there, so the Nepali hint tells people to search in English (e.g. `eat`). ARASAAC answers 404 when it finds nothing, which the app treats as "no results", not as a connection error.
- First visit, same rule in the app and the landing: a valid `?lang=` wins; otherwise the first entry of `navigator.languages` (whole list, by base code: `pt-BR` -> `pt`; the old Hebrew code `iw` counts as `he`; `zh-TW`, `zh-HK`, `zh-MO` and anything with `Hant` count as `zh-hant`, any other `zh` (also `?lang=zh`) as `zh-hans`; the function is `normLang` in both files) that TalkPics supports; otherwise English. There is no Spanish default anymore. After the first visit the app keeps the language saved in Settings: a plain `?lang=` (shared links, QR) does not change it. Exception (decided 2026-11-06 after Sebastián tested it): the landing's "Open the app" buttons add `&from=web`, and then the language chosen on the landing replaces the saved one; the app removes `from` from the URL afterwards. A stored voice is only used if it belongs to the current language, and changing language refreshes the voice list. Incognito windows in Chrome share storage while any of them is open, so a language chosen in one incognito tab sticks in the others.
- Translations of the newer languages were written without native review. Latvian was promised to the Latvian Autism Association; ask a native speaker to review before relying on it.
- Nepali (added 2026-11-07 on request of AutismCare Nepal Society, ACNS, who asked for it and were asked to review it): the app texts (cards, categories, interface, welcome help) were reviewed by ACNS (Surendra Bajracharya, director) and applied on 2026-11-11. Still NOT reviewed: the landing page (`data-ne` spans and the `ne` entries of `TP_MSG`, `CF_*`, `QR_ALT`, `TITLES` in `index.html`), `A11Y_STR.ne`, `creditsBody`, and five strings kept from the first version because the English reference in the review list did not match what the Nepali text has to say (`fldName`, `fldNameLoc`, `stVoiceHelp`, `arasaacPh`, the "search in English" sentence of `arasaacHint`). ACNS terms to keep: श्रेणी (category), चित्र सङ्केत (pictogram), उपकरण (device), बालबालिका मोड / सम्पादन मोड, साझा गर्नुहोस् (share), वैकल्पिक (optional); action cards end in -ने (खेल्ने). The card Calor is गर्मी (ACNS wrote "गर्मी / तातो"; the card is spoken aloud, so only one word). Nepali shows numbers in Devanagari digits: `locNum()` converts `{N}` and `{n}` for `ne` only. The review files are `TalkPics_nepali_revision_ACNS.xlsx` (sent) and `TalkPics_nepali_revision_ACNS_Reviewed.xlsx` (received), not in the repo. Nepali needs a Devanagari font on the device (all current Android and iOS have one). `LANG_LINE` only holds es/ca/en (it replaces the old flags line); the newer languages carry their own language line inside `welcomeBody`, so `ne` is not added there. The landing says "17 languages" in the advantages text (#81, and the list in #82) and in the static `meta description` / `og:description`; update those when adding another language.
- Hebrew and Arabic (added 2026-11-08 at the request of Beit Issie Shapiro, Israel, who needs both): translations NOT reviewed by native speakers; ask Beit Issie Shapiro to review before presenting them as verified. Arabic is Modern Standard Arabic only (no dialect entry; Palestinian and other dialects would be a family's own names via `p.names.ar`). Both languages mark gender: card names (Feliz, Cansado, Tengo hambre, No sé…) use the masculine singular like the Spanish source, so a family with a girl may want to rename them (edit sheet). The Hebrew interface avoids gender with infinitives and "אפשר ל…"; the Arabic interface uses the usual masculine imperative. Arabic action cards are first person ("ألعب" = I play), Hebrew ones infinitive ("לשחק"). When reviewed lists come back, apply them to `BASE_NAMES`, `BASE_CATS`, `V17_NAMES`, `I18N_EXTRA`, `A11Y_STR`, `MODEL_LINE` (keys `he`/`ar`) in `TalkPics.html` and to the `data-he`/`data-ar` spans and the `he`/`ar` entries of `TP_MSG`, `CF_*`, `QR_ALT`, `TITLES` in `index.html`.
- Chinese, Japanese and Korean (added 2026-11-08, nobody requested them yet; translations NOT reviewed by native speakers). Codes are lowercase with a hyphen: `zh-hans` and `zh-hant` (the `?lang=` value is lowercased, so never use `zh-Hans`). `<html lang>` takes the code, which also makes the browser pick Chinese glyphs. On the landing they are `data-zh-hans`/`data-zh-hant` spans and `body.zh-hans` classes. Simplified = mainland vocabulary, Mandarin voice (`zh-CN`, then `zh-TW`; never a Cantonese `zh-HK`/`yue` voice). Traditional = Taiwan vocabulary, voice `zh-TW`, then Cantonese `zh-HK`/`yue` (for Hong Kong), then `zh-CN`. ARASAAC is asked with `zh` for both Chinese (`ARA_CODE`) and with `ko`; Japanese goes straight to English, then Spanish. Japanese: interface in polite です/ます with kanji; cards and categories in hiragana/katakana only, casual child speech, because young children do not read kanji. Korean: interface and cards in 해요체 (polite-informal, works at home and at school; chosen by Sebastián); nouns stay plain. No gender in these four languages. CSS: CJK header labels get `white-space:nowrap` (otherwise they break one character per line) and Korean uses `word-break:keep-all` (breaks by word, as Koreans write).
- Editor header on phones (≤440 px, `body.care`): the mode label goes under "TalkPics", the 🗣️ is hidden and the buttons are a bit tighter (touch targets stay ≥64 px), so the header fits 390 px in all 17 languages (it used to overflow in every language). At 375 px German and Russian still overflow by a few px.

## Access and speech options (added 2026-11-16, from the OpenAAC developer checklist)
Source: https://www.openaac.org/considerations . Everything here is off by default and turned on in Settings, so existing installs see no change. The settings keys are `cols`, `labels`, `contrast`, `tap`, `holdMs`, `debounce`, `quick`, `quickPhrases`, `alert`, `tools`; a missing key means the default, so old backups and exported apps keep working.
- Fixed columns (`cols`: 0 = automatic, or 2–8): `#grid` gets the class `fixed` and `--cols`. With a fixed number each card stays in the same place on every screen and rotation (motor planning). In child mode the order is always `pos`; the sort menu only affects the editor.
- Moving a card: "Move earlier / Move later" in the edit sheet (`movePic`) swaps `pos` with the neighbour in the same category. There is no drag and drop.
- `labels`: `both`, `img` (photo only) or `text` (text only), as body classes `lbl-img` / `lbl-text`.
- `contrast`: body class `hc` (black background, white text, yellow accent). A new component with its own colours needs a `body.hc` rule; check it with axe.
- How a card is chosen (`tap`): `release` (a click, as always), `press` (on pointerdown) or `hold` (`holdMs`, 300–2000 ms, with a filling bar). `bindSelect` wires it; the editor always uses `release`, and Enter/Space always select. After a `press` or `hold` selection the click that follows the finger lifting is swallowed (`swallowClick`), otherwise it would land on the zoomed picture. `debounce` (0, 500, 1000, 2000 ms) ignores repeated selections in `trySelect`. Known limit: with `press`, scrolling by dragging on a card selects it.
- Talk bar (`#talkbar`, shown when `quick`, `alert` or `tools` is on): quick phrases (`quickList()`; the four defaults are keys `qpWait`, `qpHelp`, `qpStop`, `qpBreak` so they follow the language, custom ones are `{text}`), a help button (three tones, then `qpHelp` at full volume even if "Speak aloud" is off), "repeat louder" (TTS volume 1; a recorded voice is amplified ×2 with Web Audio) and "show the text" (`#showScrim`: the last message in the biggest type that fits without splitting words; tapping it rotates it 180° for someone sitting opposite). `lastSaid` holds the last thing said; `currentMessage()` prefers the sentence strip when it has pictures. If "Speak aloud" is off, a quick phrase and "repeat louder" show the text instead.
- Print (`printBoard`): fills `#printArea` with one section per category and calls `window.print()`; `@media print` hides the app. It is the paper backup.
- Open Board Format: `buildObz` writes a `.obz` (a zip made by hand, stored without compression: `zipStore`, `crc32`) with a home board (one button per category), one board per category, the images and the recorded voices. `importObf` reads `.obf` and `.obz` (stored or deflate, the latter through `DecompressionStream`): each board becomes a new category and each button with a label a new card; buttons that only open another board are skipped; imported images are redrawn as 500 px JPEG on white, so "export without photos" treats them as personal photos. It adds, it never replaces. The structure was checked against the reference validator (https://github.com/open-aac/obf, `lib/obf/validator.rb`), not against other AAC apps: importing a TalkPics `.obz` into another app is NOT tested. TalkPics-only data goes in `ext_talkpics_*` button attributes.
- Texts: `OPENAAC_STR` (17 languages, 58 keys, none reviewed by native speakers; `{a1}`, `{a2}`, `{/a}` in `resBody` become the OpenAAC links). Seconds are formatted by `fmtSecs` with the language's own number format.
- Keyboard for typing (`keys`, added 2026-11-16): a ⌨️ button in the talk bar opens `#kbScrim`, a text box with big keys in alphabetical order (`KB_ALPHA`: es, ca, en, fr, it, pt, de, lv, uk, ru, he, ar, each with its own letters and accents) plus space, punctuation, delete one letter and clear all. "Say it" (or Enter) speaks the text; 👀 shows it large. The text box has `inputmode="none"` so the device keyboard stays closed; "Use the device keyboard" (`kbDevice`) switches to it and moves the buttons to the top so the keyboard does not cover them. ne, zh-hans, zh-hant, ja and ko have no big keys (their scripts need the device's own input method) and always use the device keyboard. No word prediction, no letter-by-letter voice. Not tested with a real on-screen keyboard.
- ARASAAC skin tone (`araSkin`, added 2026-11-16): five swatches in the search sheet (`ARA_SKINS`: white, assian, aztec, mulatto, black; `assian` is the API's own spelling). For results with `skin:true` the thumbnail and the chosen picture come from `https://api.arasaac.org/api/pictograms/{id}?download=false&skin=…` (500 px, CORS open) instead of the static 300 px file. Pictograms without skin, and some with several people, do not change. Verified against the live API on 2026-11-16. Hair colour (`hair=`) is not offered.
- Remove the background of a photo (added 2026-11-16): a button in the edit sheet, only for photos (JPEG data URLs that are not ARASAAC pictograms). It runs on the device with ONNX Runtime Web 1.31.1 (MIT) and the small U²-Net model `u2netp.onnx` (Apache 2.0), both in `bg/` (about 19.5 MB; licences in `bg/LICENSES.txt`, credit line `bgCredit` in Settings). `removeBackground` scales the photo to 320×320, runs the model on one thread (GitHub Pages is not cross-origin isolated), stretches the mask back and puts the subject on white; `pending.imgOrig` keeps the original until the card is saved ("Back to the original photo"). The files are fetched the first time the button is used, never at install. `sw.js` keeps them in their own cache (`BG_CACHE`, `tp-bgtool-1`) that survives `VERSION` changes; bump that name if the files in `bg/` change. An exported or file:// copy of the app, or one served from another origin, loads them from `BG_PUBLIC` (the public site), so there it needs internet every time. Do not rename or move `bg/`. Checked on 2026-11-16 after publishing, in headless desktop Chrome: the live site (with the service worker cache), another origin and a file:// copy all work; GitHub Pages serves the files gzip-compressed, about 8 MB in total, which is the figure the help text (`bgHelp`) gives; 2–5 s per photo. Not measured on a phone.
- Landing page (`index.html`): since 2026-11-16 the features grid has six more cards for these options (background removal, keyboard, quick phrases and help, access options, printing, Open Board Format), in the 17 languages, not reviewed by native speakers. The keyboard card does not mention large keys in ne, zh-hans, zh-hant, ja and ko, because those languages only use the device keyboard. The install notes say that ARASAAC search and, the first time, background removal need internet.
- Zoom on open (added 2026-11-19): two-finger pinch zoom is allowed (accessibility, decided 2026-11-07), but Android keeps an installed app in memory, so an accidental pinch (a child touching with two fingers) stayed when the app was reopened: the board looked zoomed in and cut off. On `pageshow` and when the app becomes visible again, if `visualViewport.scale` > 1.01 it adds `maximum-scale=1` to the viewport meta for 400 ms and then removes it; if the app is still zoomed it reloads, but only when no sheet (except the welcome sheet) and no big picture (`#zoom`) are open, so a photo being added or edited is never lost. Pinch zoom keeps working afterwards. Checked in headless Chrome with emulated touch at 800×1280: the reload path resets the zoom; whether the `maximum-scale` toggle alone resets it could not be checked there (emulated Chrome ignores viewport changes after load) and has not been checked on a real Android device.
- Categories on phones (added 2026-11-20): at ≤600 px the category bar (`#cats`) is one row that scrolls sideways instead of wrapping (8 categories wrapped to 4 rows, 237 px, which with the header took 57% of a 320×568 screen and 38–44% of usual phones; now 69 px, 17–27%). `renderCats` scrolls the active category into view; `catEdges` adds `more-start`/`more-end` so the edge that hides more categories fades (CSS mask, with `[dir=rtl]` mirrors). Tablets and desktop still wrap. Checked in headless Chrome at 320–430 px in en, de, ru and ar.
- Not done on purpose: usage logging (it would break the no-tracking promise), switch scanning, word prediction.
